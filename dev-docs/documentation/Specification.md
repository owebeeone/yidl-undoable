# Undoable end-user documentation specification

User authorization: apply the Lifecycle documentation approach to Undoable, with
progressive practical examples, complete reference and independent review before
publication. The specialized/cache integration is separately authorized in
[the integration boundary](../SpecializedAccessorIntegration.md).

Editable here: README, public guides/reference, standalone examples, contributor
instructions and docs-only build/deployment configuration. SDKs, Lifecycle, Cache
and Dataclass implementation are reference-only. No package release is included.

Lead with an edit/undo/redo payoff, then explain rollback versus navigation,
managed versus nonversioned storage, live views versus pinned snapshots, root
membership, branched redo, providers and validation. Each package stands alone;
reading Lifecycle is not a prerequisite. Reuse worked examples before general
rules and keep optional prediction prompts answerable directly in the text.

Callback claims must follow Undoable, not an assumed identical Lifecycle contract.
In particular generated cls, generic transient providers, full rooted-candidate
validation and initvar retention differ. Maintain existing API/Architecture URLs,
retain exact failure/compare semantics in reference and expose installation limits.

Execute all examples and complete guide blocks; build strictly, validate local
links/assets/search/exclusions, then get independent adversarial review before
push. Public Pages output excludes validation/development records. Preserve the
original experiment evidence as repository links rather than introductory material.
No usability/retention improvement is claimed without observing real readers.
